# ТЗ — Корректность расчёта НДФЛ (ст. 214.2 + имущество, ОМС/валюта)

> Спек от архитектора (`docs/ai/architect.md`, §5, «полная задача»).
> Закрывает **системный дефект**: ядро `calculateTax` кодифицирует устаревший/гибридный расчёт
> необлагаемого лимита (доставшийся 1:1 из legacy `script.js`), а модули ОМС/валюты переиспользуют
> депозитную налоговую логику там, где она юридически неприменима. Налог **занижается** на крупных
> вкладах и считается **неверно** для металлов и валюты.
>
> ⚠️ **Юридическая основа (нормы НК РФ, актуально на 2025–2026):**
> - **Ст. 214.2** (рублёвые и валютные проценты): необлагаемый лимит = `1 000 000 × макс. ключевая
>   ставка ЦБ на 1-е число месяцев года дохода`. С 2025 — ставка **13%** до **2,4 млн**, **15%** свыше
>   (отдельно от зарплаты). Проценты по эскроу и по вкладам со ставкой **≤ 1%** в базу **не входят**.
>   Проценты по валютному вкладу пересчитываются в рубли по курсу ЦБ **на дату зачисления** и
>   суммируются с рублёвыми под единый лимит.
> - **Ст. 217 п.17.1 + ст. 220** (ОМС и продажа валюты = имущество): срок владения **≥ 3 лет** →
>   доход освобождён (**0%**). При сроке **< 3 лет**: база = `доход − подтверждённые расходы`;
>   если документов нет — имущественный вычет **250 000 ₽/год** (к доходу, **не** к прибыли;
>   **взаимоисключающе** с расходами). Затем 13% до 2,4 млн, 15% свыше.
> - **Курсовая разница тела валютного вклада/наличной валюты налогом НЕ облагается.**

## 🏗 Архитектурный разбор & Blast Radius

**Проблема (по убыванию критичности, все — в `src/shared/`):**

1. **`tax.ts:11`** — `THRESHOLD_13_PCT = 5_000_000`. Порог 13%→15% для вкладов и имущества с 2025 =
   **2 400 000**, а не 5 млн (5 млн — устаревший общий порог 2024).
2. **`tax.ts:28-30`** — лимит считается как `max(maxBalance, 1_000_000) × effectiveRate`. Правильно:
   **`1_000_000 × cbrRate`** (база — константа, **не** зависит от суммы вклада). Это гибрид старой
   (до 2021) формулы `ставка × остаток` и новой → лимит раздувается пропорционально вкладу.
3. **`tax.ts:10,28`** — `MIN_CBR_RATE = 0.13`, `max(cbrRate, 13%)`. 13% — это ставка НДФЛ, к ключевой
   ставке ЦБ отношения не имеет. Латентно (при ставке > 13% не влияет), но при низкой ставке ЦБ
   завышает лимит почти вдвое.
4. **`asset.ts:33`** — `calculateTax([Math.max(profit, 0)], amount, keyRate)` применяется к ОМС и
   валюте как ко вкладу. Это **другой режим** (имущество): нет правила «≥ 3 года = 0», нет вычета
   250 000 ₽, применяется неприменимый депозитный лимит.
5. **`currency.ts` / `asset.ts:20-21`** — `profit = units × sellPrice − amount` (курсовая разница
   тела) подаётся как облагаемый доход. Курсовая разница налогом **не** облагается.
6. **`tax.ts:46-51`** — порог 2,4 млн накапливается по годам (`totalTaxable`), а должен
   **сбрасываться** каждый календарный год (лимит базы — годовой).
7. **`bank.ts`** — нет исключений для вкладов ≤ 1% и эскроу (облагаются все).
8. **`retail.ts:82`** — к прибыли розницы применяется ст. 214.2 (неприменима к торговле).

**Blast radius (читано целиком):** `src/shared/tax.ts`, `src/shared/asset.ts`, `src/shared/types.ts`,
`src/calculators/bank.ts`, `src/calculators/metals.ts`, `src/calculators/currency.ts`,
`src/calculators/retail.ts`, `index.html`. → **8 сущностей > 4** ⇒ задача дробится на фазы
(§1.3 архитектора). Каждая фаза — отдельный PR, независимо тестируемый и не ломающий остальные
калькуляторы.

**Декомпозиция (3 фазы):**
- **Фаза A — ядро + банк** (3 сущности): `tax.ts`, `types.ts`, `bank.ts`. Чинит депозитный расчёт,
  не трогает имущество. После неё bank-калькулятор считает верно.
- **Фаза B — имущество (ОМС + валюта)** (≤4 сущности на подфазу): новая функция property-tax в
  `asset.ts` + `types.ts`; проводка в `metals.ts` + UI metals в `index.html`; проводка в
  `currency.ts` + UI currency в `index.html`. Разделена на B1/B2/B3.
- **Фаза C — edge-cases** (2 сущности): исключения ≤1%/эскроу в `bank.ts`; снятие НДФЛ с `retail.ts`.

> **Порядок строго A → B → C.** Фаза A меняет сигнатуру `calculateTax`, на которую опирается B/C.

### 🔹 Фаза A — Ядро `calculateTax` (депозитный режим, ст. 214.2)

**Сущности:** `src/shared/tax.ts`, `src/shared/types.ts`, `src/calculators/bank.ts`.

#### A.1 `src/shared/tax.ts` — переделать расчёт

Псевдокод новой `calculateTax` (сигнатура **сохраняется**: `(profitByYear, maxBalance, cbrRate)` —
`maxBalance` остаётся параметром для обратной совместимости, но **больше не** множит лимит; см. A.3):

```
константы:
  TAX_FREE_BASE   = 1_000_000        // база лимита — КОНСТАНТА (ст. 214.2)
  THRESHOLD_13    = 2_400_000        // граница 13%→15% (было ошибочно 5_000_000)
  RATE_13         = 0.13
  RATE_15         = 0.15
  // MIN_CBR_RATE — УДАЛИТЬ (флор ставки ЦБ на 13% некорректен)

calculateTax(profitByYear, _maxBalance, cbrRate) -> TaxResult:
  // лимит — КОНСТАНТА × ставка, БЕЗ max(balance, ...) и БЕЗ floor на 13%
  yearlyLimit   = TAX_FREE_BASE * (cbrRate / 100)
  totalTax      = 0
  totalTaxable  = 0
  totalTaxFree  = 0

  для каждого yearProfit в profitByYear:
    // порог 2,4 млн — ГОДОВОЙ, сбрасывается каждый год (НЕ накапливается)
    if yearProfit <= yearlyLimit:
      totalTaxFree += yearProfit            // весь годовой доход в лимите — налог 0
      continue

    taxableThisYear = yearProfit - yearlyLimit
    totalTaxFree   += yearlyLimit
    // ставка применяется к taxableThisYear относительно ГОДОВОГО порога 2,4 млн:
    if taxableThisYear <= THRESHOLD_13:
      taxThisYear = taxableThisYear * RATE_13
    else:
      taxThisYear = THRESHOLD_13 * RATE_13 + (taxableThisYear - THRESHOLD_13) * RATE_15
    totalTax   += taxThisYear
    totalTaxable += taxableThisYear

  return { yearlyLimit, taxableIncome: totalTaxable, taxAmount: totalTax, taxFreeUsed: totalTaxFree }
```

**Ключевые изменения vs текущего кода:**
1. `taxFreeBase = TAX_FREE_BASE * (cbrRate/100)` — **убрать** `max(maxBalance, 1_000_000)`.
2. `effectiveRate = cbrRate/100` — **убрать** `Math.max(cbrRate, MIN_CBR_RATE)`. Удалить константу
   `MIN_CBR_RATE`.
3. `THRESHOLD_13_PCT` → переименовать в `THRESHOLD_13 = 2_400_000` (значение **5_000_000 → 2_400_000**).
4. Порог 2,4 млн применяется **к `taxableThisYear`** (годовая база), а не к накопленному
   `totalTaxable`. Убрать аккумуляцию `totalTaxable` в условие ставки.

> `_maxBalance` в сигнатуре помечен как неиспользуемый (подчёркивание) — сохраняем ради совместимости
> с вызывающими сторонами; это намеренный компромисс миграции (не ломать сразу все колл-сайты).
> В JSDoc явно указать: «параметр оставлен для обратной совместимости, на расчёт не влияет; лимит
> по ст. 214.2 = 1 000 000 × cbrRate».

#### A.2 `src/shared/types.ts` — обновить JSDoc `TaxResult`

Поле `yearlyLimit` переписать: «`1 000_000 × cbrRate` (ст. 214.2); не зависит от суммы вклада».
Структура полей **не меняется** — обратно-совместимо.

#### A.3 `src/calculators/bank.ts` — без изменений логики, только проверка

`calculateBankProfit` уже вызывает `calculateTax(profitByYear, maxBalance, cbrRate)` — сигнатура та
же, правка не требуется. **Кодер обязан** прогнать ручные кейсы (см. 🧪) и убедиться, что цифры в

### 🔹 Фаза B — Имущество (ОМС + валюта), ст. 217/220

> Цель: ОМС и валюта считают налог как **продажу имущества**, не как вклад. Вводится отдельная
> чистая функция property-tax; депозитная `calculateTax` к ним **больше не применяется**.

#### B.1 `src/shared/asset.ts` + `src/shared/types.ts` — функция property-tax

**B.1.1 `types.ts`** — новый интерфейс + расширить `AssetRoundTripParams`:

```
// добавить в AssetRoundTripParams:
hasPurchaseDocs: boolean   // есть документы на покупку (true по умолчанию в UI)
// refPrice/keyRate/holdPeriod/amount/buyPrice/sellPrice — без изменений

// новый тип:
PropertyTaxResult {
  isExempt: boolean        // срок владения ≥ 3 года → налог 0
  holdingYears: number     // holdPeriod / 365 (для отображения)
  deductionApplied: number // 250 000 если применён вычет, иначе 0
  taxableIncome: number    // итоговая база (≥ 0)
  taxAmount: number        // НДФЛ (13% до 2,4 млн, 15% свыше)
}
```

**B.1.2 `asset.ts`** — новая чистая функция `calculatePropertyTax` (рядом с
`calculateAssetRoundTrip`; константы порогов/ставок — свои именованные, не дублировать с tax.ts
без нужды — можно импортировать общие из нового мини-модуля, но **без новой зависимости**):

```
константы:
  HOLD_YEARS_EXEMPT = 3           // срок владения для освобождения (ст. 217 п.17.1)
  DAYS_PER_YEAR     = 365
  PROPERTY_DEDUCTION = 250_000    // вычет при отсутствии документов (ст. 220)
  THRESHOLD_13      = 2_400_000   // тот же, что во вкладах
  RATE_13 = 0.13, RATE_15 = 0.15

calculatePropertyTax(params) -> PropertyTaxResult:
  { rubAfterSell, purchaseCost, hasPurchaseDocs, holdPeriod } = params
  holdingYears = holdPeriod / DAYS_PER_YEAR
  if holdingYears >= HOLD_YEERS_EXEMPT:
    return { isExempt: true, holdingYears, deductionApplied: 0, taxableIncome: 0, taxAmount: 0 }

  // режим «< 3 лет»: либо расходы, либо вычет 250к — ВЗАИМОИСКЛЮЧАЮЩЕ
  if hasPurchaseDocs:
    base = max(rubAfterSell - purchaseCost, 0)
    deductionApplied = 0
  else:
    base = max(rubAfterSell - PROPERTY_DEDUCTION, 0)
    deductionApplied = PROPERTY_DEDUCTION

  if base <= THRESHOLD_13:
    tax = base * RATE_13
  else:
    tax = THRESHOLD_13 * RATE_13 + (base - THRESHOLD_13) * RATE_15
  return { isExempt: false, holdingYears, deductionApplied, taxableIncome: base, taxAmount: tax }
```

> `purchaseCost` — это `amount` (сумма покупки в рублях). В `AssetRoundTripParams` уже есть `amount`;
> внутри `calculateAssetRoundTrip` прокинуть его в `calculatePropertyTax` как `purchaseCost`.

**B.1.3 `asset.ts` — `calculateAssetRoundTrip`** перевести на property-tax:

- **Убрать** вызов `calculateTax([Math.max(profit,0)], amount, keyRate)` (стр. 33).
- **Вместо** него: `const propertyTax = calculatePropertyTax({ rubAfterSell, purchaseCost: amount,
  hasPurchaseDocs, holdPeriod })`.
- Поле `tax: TaxResult` в `AssetRoundTripResult` — **заменить** на `tax: PropertyTaxResult`.
  **Внимание:** это ломает `metals.ts`/`currency.ts` — они читают `r.tax.yearlyLimit` и др. →
  правятся в B.2/B.3 (поэтому B — одна связанная фаза, нельзя релизить частично).
- `finalAmount = rubAfterSell - propertyTax.taxAmount` (без изменений по сути).
- `profit` (курсовая разница) **остаётся** в результате для отображения доходности/спреда, но в налог
  **не идёт**. В UI нужно явно подписать, что это «изменение стоимости» и налогом не облагается (B.2/B.3).

## 🛡 Граничные случаи & Защита архитектуры

- **Деление на ноль:** `buyPrice = 0` в `asset.ts` уже невозможен (валидация в calculator'ах), но
  `calculatePropertyTax` должен defensively обрабатывать `rubAfterSell <= 0` → `taxableIncome = 0`.
- **Отрицательная база:** `max(rubAfterSell - cost, 0)` и `max(rubAfterSell - 250_000, 0)` —
  убыток налогом не облагается (база = 0), перенос убытков **не** реализуем (вне scope).
- **`holdPeriod = 0`:** валидируется в calculator'ах (`metal-hold-period`/`currency-hold-period` min=1);
  в `calculatePropertyTax` при `holdPeriod <= 0` → `holdingYears = 0`, не exempt, база по общему правилу.
- **Порог 3 года на днях:** `3 × 365 = 1095 дней`. Это **приближение** (по НК — 3 полных календарных
  года, високосные учитываются иначе). Оговорить в UI: «срок ≥ 3 лет (≈ 1095 дней)». Не считать по
  точным датам — это **отдельная фича** (ЭССКАЛИРОВАТЬ при необходимости).
- **Вычет 250 000 — годовой лимит** на ВСЁ имущество за год, не на объект. Калькулятор считает один
  объект — упрощённо применяет вычет целиком. Оговорить в UI.
- **Безопасность:** все записи в DOM — только через `textContent`/`createTextNode` (AGENTS.md §7).
  Никакого `innerHTML` с вычисленными значениями. Текст «освобождено, ≥ 3 лет» — литерал, безопасен.
- **Без новых зависимостей.** `fetch` к ЦБ не трогается (он уже под таймаутом/кешем, §8.1/§8.2).
- **Обратная совместимость типов:** замена `AssetRoundTripResult.tax: TaxResult` на
  `PropertyTaxResult` — **ломающее** изменение, но потребители только `metals.ts`/`currency.ts`
  (правятся в той же фазе B). Внешнего API нет.
