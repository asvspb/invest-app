# Дополнение к ТЗ — Двухколоночная раскладка (форма | результаты)

> Дополнение к `docs/plan-design-saas.md`. Базовый редизайн (табы, токены, тема) уже реализован
> кодером (незакоммичено на `feat/vite-ts-migration`). Эта правка меняет **внутреннюю раскладку
> таб-панели**: вертикальная простыня → форма слева, результаты справа от кнопки «Рассчитать».
> Запрос заказчика: умещать калькулятор на один экран без общего скролла страницы.

## 🏗 Контекст и blast radius

**Текущее состояние (после базового редизайна):**
- Табы, токены, тема — реализованы (`src/styles/*.css`, `src/ui/`, `index.html`).
- НО внутри таб-панели layout **вертикальный**: `.tab-panel { max-width: 480px }` (`layout.css`),
  форма и `.result` идут друг за другом в одной колонке → отсюда скролл.

**Замерено архитектором (фактические размеры):**

| Калькулятор | Полей формы | Строк результата | Уместится без скролла в 2 колонки? |
|---|---|---|---|
| Банк | 5 | ~15 | ✅ да |
| Ретейл | 10 | ~30 | ❌ — нужен внутренний скролл у результатов |
| Валюта | 11 | ~32 | ❌ |
| Металлы | 11 | ~32 | ❌ |

**Решение архитектора (заказчик не ответил — беру рекомендованный вариант):**
двухколоночная раскладка; правая колонка результатов получает **собственный вертикальный скролл**
(`overflow-y: auto` с `max-height`), форма слева **всегда видна и не уезжает**. Это реализует
суть запроса «не терять контекст ввода при просмотре результатов», сохраняет читаемость и не режет
функционал. Банк уложится без скролла вообще.

**Blast radius:**
- `index.html` — **обернуть** форму в `.calc-form`, результаты в `.calc-result` внутри каждого
  `.calculator-container`. Все `id`/`onclick`/`invest-*` классы **сохранить**.
- `src/styles/layout.css` (или новый `src/styles/calculator-layout.css`) — flex-сетка 2 колонки.
- `src/styles/components.css` — `.result` убрать `margin-top`, стать self-contained колонкой.
- **Не трогать**: `src/calculators/*`, `src/shared/*`, `server/*`, бизнес-логику, эндпоинты.

**Сущностей: 3** (`index.html` — обёртки, `src/styles/*` — сетка, проверка регрессии) < 4 → краткий формат.

## 📋 Детальное ТЗ

### 1. HTML: обёртки формы и результатов (`index.html`)

Внутри каждого `<div class="calculator-container">` (4 калькулятора, одинаково) — обернуть:

**Было** (вертикально):
```html
<div class="calculator-container">
    <h2 class="calculator-title">...</h2>
    <form> ... поля ... </form>
    <div class="button-group"> ... кнопки ... </div>
    <div class="result"> ... вывод ... </div>
</div>
```

**Стало** (две колонки):
```html
<div class="calculator-container">
    <div class="calc-layout">
        <div class="calc-form">
            <h2 class="calculator-title">...</h2>
            <form> ... поля ... </form>
            <div class="button-group"> ... кнопки ... </div>
        </div>
        <div class="calc-result">
            <div class="result"> ... вывод ... </div>
        </div>
    </div>
</div>
```

**Правила (точно):**
- Кнопка «Рассчитать» остаётся **в левой колонке** (внутри `.calc-form`, после полей) — как просил
  заказчик («результаты вправо от кнопки»).
- `.result` переносится в правую колонку `.calc-result` **целиком**, без изменений внутренностей.
- Все `id`, `onclick`, классы `invest-*` — **не трогать**.
- Применить к **всем 4** калькуляторам одинаково (bank/retail/currency/metals).

### 2. CSS: двухколоночная сетка (`src/styles/layout.css` или новый файл)

```css
.calc-layout {
    display: grid;
    grid-template-columns: minmax(320px, 1fr) minmax(320px, 1fr);
    gap: 2rem;
    align-items: start;        /* колонки выровнены по верху */
}

.calc-form {
    /* форма: без изменений стилей, просто колонка */
}

.calc-result {
    /* правая колонка: результаты с внутренним скроллом у тяжёлых калькуляторов */
    position: sticky;
    top: 5rem;                   /* под sticky-хедером с табами */
    max-height: calc(100vh - 7rem);
    overflow-y: auto;            /* внутренний скролл ТОЛЬКО у результатов */
    padding-right: 0.5rem;       /* место под скроллбар */
}

/* Адаптив: на узких экранах колонки складываются вертикально */
@media (max-width: 860px) {
    .calc-layout {
        grid-template-columns: 1fr;
    }
    .calc-result {
        position: static;
        max-height: none;
        overflow-y: visible;
    }
}
```

**Ключевые свойства:**
- `grid` 2 колонки — форма слева, результаты справа.
- `align-items: start` — колонки не растягиваются по высоте друг друга.
- `.calc-result` — `position: sticky` + `max-height: calc(100vh - 7rem)` + `overflow-y: auto`:
  правая колонка прилипает под хедером, при длинных результатах скроллится **внутри себя**,
  форма остаётся видимой. `7rem` = хедер (~4rem) + padding.
- `@media (max-width: 860px)` — на мобильных/планшетах складывается в 1 колонку (без скролла внутри).

### 3. CSS: `.result` убрать вертикальные отступы-разделители

В `src/styles/components.css` текущий `.result` имеет `margin-top: 1.5rem; border-top: ...`
(разделитель между формой и результатом). В двухколоночной раскладке это лишнее — колонки
уже разделены gap. Правка:
```css
.result {
    /* margin-top: 1.5rem; — убрать (был разделитель при вертикальной раскладке) */
    /* border-top: 2px solid ...; — убрать */
    /* оставить: padding, фон если есть */
}
```

### 4. Контракт (критично — НЕ ломать)

- **Все `id` сохраняются** — `profit`, `metal-*`, `currency-*`, `retail-*` и т.д. Перенос `.result`
  в другой div не меняет id; `byId()` в калькуляторах продолжит работать.
- **`onclick` не трогаются** — кнопка «Рассчитать» остаётся в форме.
- **Классы `profit-positive`/`profit-negative`/`loading`** — на месте, стили через токены работают.
- **После сборки** — обязательная ручная проверка всех 4 калькуляторов: расчёт срабатывает,
  результаты попадают в правую колонку, id не потеряны (TD не ловит пропуски DOM-id).

## 🛡 Граничные случаи & Защита архитектуры

- **Тяжёлые калькуляторы** (retail/currency/metals, ~30 строк): правая колонка скроллится внутри
  себя, форма не уезжает — это и есть цель «не терять контекст». Банк (5 полей) — без скролла.
- **Sticky-хедер с табами** (`position: sticky; top: 0`) уже есть — `.calc-result` с `top: 5rem`
  аккуратно ложится под ним, не перекрывая.
- **Мобильные (<860px)**: одна колонка, `position: static` — обычный вертикальный поток
  (без скролла внутри, скролл страницы). Это приемлемо на мобильных (там 2 колонки нечитаемы).
- **Длинный label/число**: `minmax(320px, 1fr)` — колонки не схлопываются меньше 320px,
  перенос слов работает.
- **Модалка** (`#calculationModal`) вне `.calc-layout` — z-index выше, не затрагивается.
- **Тема**: двухколоночная раскладка не зависит от темы — токены (`--color-surface`, `--color-divider`)
  работают в обеих.

## 🧪 Проверочные кейсы (ручные)

**A. Раскладка:**
| Проверка | Ожидание |
|---|---|
| Широкий десктоп (≥860px), таб «Банк» | 2 колонки: форма слева, результаты справа; **без скролла страницы** |
| Таб «Металлы» (30+ строк) | форма слева видна постоянно; правая колонка скроллится внутри себя при наведении |
| Узкий экран (<860px) | 1 колонка, обычный вертикальный поток |

**B. Контракт (регрессия расчётов — критично):**
| Калькулятор | Вход | Ожидание (как до редизайна) |
|---|---|---|
| Банк | 100000/12/10%/реинвест | profit=2 521 ₽, final=102 521 ₽ |
| Валюта | 100000/95/92/ref90/21/30 | profit=−3 157 ₽ |
| Металлы | Au 100000/10000/10200/ref10100/365 | profit=+2 000 ₽ |

Числа не должны измениться — правка **строго layout**, расчёты не трогаются.

**C. id-контракт:**
| Проверка | Ожидание |
|---|---|
| `byId('profit')` в bank.ts не бросает | форма считает и пишет в правую колонку |
| `byId('metal-result')` в metals.ts не бросает | аналогично |
| `grep -oE 'id="[^"]+"' index.html \| sort \| uniq -d` | нет дублей id |

## ⚠ Что НЕ делать (anti-scope)

- **Не трогать** `src/calculators/*`, `src/shared/*`, `server/*`, бизнес-логику.
- **Не менять** `id`, `onclick`, классы `invest-*` — только обернуть в `.calc-layout`/`.calc-form`/`.calc-result`.
- **Не сокращать** метрики и не уплотнять вывод (заказчик не выбрал это) — скролл у результатов,
  не обрезание данных.
- **Не трогать** табы/токены/тему (уже работают) — только внутренняя раскладка таб-панели.
- **Не вводить** CSS-фреймворк (Tailwind и т.д.) — vanilla CSS grid.
