### 1. Рабочий процесс (СТРОГО)

1. **Войди в нативный plan-mode среды** (ZCode → plan mode; antigravity → аналог; Codex/Claude →

   Репозиторий крошечный (4 исходника) — затронутые файлы читай **целиком**. Конкретно проверяй:
   - бизнес-логика в `public/script.js`: `calculateBankProfit`, `calculateRetail`,
     `calculateCurrency`, `calculateTax`;
   - контракт HTML↔JS по DOM-ID (пропуск id = тихая поломка);
   - какие эндпоинты сервера зовёт фронт: `/api/cbr-key-rate`, `/api/cbr-rates`.
3. **Дробление.** Задача **> 4 сущностей** → разбивай. **Сущность** = файл (`server.js`,

4. **ТЗ → кодер** (формат в §3).
5. **Ревью по факту** (§4).
6. **Итерация:** найден дефект → точечно уточнить ТЗ и повторить ревью. **До 2 раундов**,

### 2. Архитектурные приоритеты проекта

Проект маленький, но с растущим техдолгом (`AGENTS.md` §8). Приоритеты при проектировании:

1. **Разделение логики и DOM.** Любое изменение расчётов — держать/переводить в чистые функции
   (число → число). Образец: `calculateTax`.
2. **Изоляция внешних вызовов.** Все обращения к ЦБ — на сервере (`/api/...`), никогда на фронте.
   Каждый `/api/*` должен быть: с таймаутом (`AbortController`), с кешем, с валидацией ответа,
   с кодом ошибки.
3. **Контракт по id.** Изменение формы = явный список затронутых DOM-ID с обеих сторон в ТЗ.
4. **Нулевая зависимая магия.** Новые npm-зависимости — отдельный пункт ТЗ с обоснованием
   (лицензия, поддерживается ли, влияние на Docker-образ и вес `public/`).

### 3. ТЗ исполнителю — атомарное, обязательные поля

- **Точные абсолютные пути:** `server.js`, `public/script.js`, `public/index.html`, `public/styles.css`.
- **Алгоритм** псевдокодом (**без** готового кода — иначе крадёшь работу и валидацию у кодера).
- **Контракт HTML↔JS:** при правке форм/результатов — явный список DOM-ID с обеих сторон.
- **Edge-кейсы:**
  - фронт — пустой ввод, `NaN`, деление на ноль (`profit/initial`, `12/period`), курс = 0,
    частичный/ошибочный ответ сервера, курсор после форматирования числа;
  - сервер — таймаут/5xx от ЦБ, пустое тело, невалидный XML/HTML, конкурентный `?refresh=true`.
- **Логирование/ошибки:** try-catch с контекстом; сообщение в DOM, не `alert`.
- **Definition of Done** — из `AGENTS.md` §9 (копируй чек-лист целиком, не сокращай).

### 4. Ревью — параноидальное, по факту

Не верь отчёту кодера. **Сам перезапусти** в среде:

```
git diff
node --check server.js && node --check public/script.js
node server.js &    # затем:
curl -s localhost:7777/api/cbr-key-rate
curl -s localhost:7777/api/cbr-rates | head -c 200
kill %1
```

Ищи системно: зависший `fetch` без таймаута; тихие `.catch(()=>{})`; `alert()` в продакшен-пути;
`innerHTML` с непроверенным контентом; хардкод чисел в логике; переименованные DOM-ID без
синхронизации HTML↔JS; регэксп-парсинг ЦБ без fallback; гонку на `cachedKeyRate`; рост `script.js`
за порог 300 строк на новую сущность.

**Аппрув** — только после зелёных независимых прогонов выше + пройденного DoD из `AGENTS.md` §9.
