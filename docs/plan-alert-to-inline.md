## 🏗 Архитектурный разбор & Blast Radius

**Проблема.** 9 вызовов `alert()` блокируют UI и нарушают §7. Распределение:

| Функция | Строка | Контекст | Тип |
|---|---|---|---|
| `fetchCbrRate` | 22 | сеть/прокси, ставка ЦБ | fetch-ошибка, **общая для 4 калькуляторов** |
| `calculateBankProfit` | 148 | `amount <= 0` | валидация ввода |
| `calculateBankProfit` | 154 | `period <= 0` | валидация ввода |
| `calculateBankProfit` | 160 | `percent < 0` | валидация ввода |
| `calculateBankProfit` | 166 | `monthlyDeposit < 0` | валидация ввода |
| `fetchCbrRates` | 368 | сеть/прокси, курсы валют | fetch-ошибка |
| `calculateCurrency` | 390 | `amount <= 0` | валидация ввода |
| `calculateCurrency` | 396 | `sellRate <= 0` | валидация ввода |
| `calculateCurrency` | 402 | `buyRate <= 0` | валидация ввода |

**Blast radius (читано целиком):**
- `public/script.js` — **единственный затрагиваемый файл**. Точечные правки в 4 функциях.
- `public/index.html` — **только если** потребуется новая DOM-якорь для `fetchCbrRate` (см. ниже).
  В большинстве случаев переиспользуются **уже существующие** span'ы результатов.
- `public/styles.css` — опционально: класс `.error-message` для единообразия (если кодер сочтёт
  нужным; обязательно — только если视觉效果 отличается между калькуляторами).
- Бизнес-логика, эндпоинты, контракт HTML↔JS по `metal-*` / `currency-*` id — **не затрагиваются**.

**Установившийся паттерн (ОБРАЗЕЦ, копировать, не изобретать):**
```js
const messageEl = document.getElementById('retail-profit-amount');  // якорь-результат
// ...валидация...
if (isNaN(revenue) || revenue < 0) {
    messageEl.textContent = 'Введите корректную выручку';  // ← inline, НЕ alert
    revenueInput.focus();
    return;
}
// ...успех: перезаписывается числом...
document.getElementById('retail-profit-amount').textContent = formatNumber(profit) + ' ₽';
```
Ключевые свойства образца: (1) `messageEl` — это span результата, который при успехе всё равно
перезаписывается; (2) `focus()` на виновное поле; (3) ранний `return`. То же в `calculateMetal`.

**Сущностей: 1** (`public/script.js`, точечные правки). Полный формат избыточен, но приведён
ради edge-кейсов и проверочных кейсов.

## 📋 Детальное ТЗ

### Паттерн A — валидация ввода (5 alert: банк ×4, валюта ×3)

Для каждой проверки заменить `alert(msg); input.focus(); return;` на:
```js
messageEl.textContent = msg;
input.focus();
return;
```
где `messageEl` — главный span результата соответствующего калькулятора.

**`calculateBankProfit` (script.js:148,154,160,166):**
- добавить в начале функции: `const messageEl = document.getElementById('profit');`
  (это `<span id="profit">` — `index.html:58`, главный заголовок результата банка).
- 4 alert → `messageEl.textContent = '...'`; тексты оставить как есть, только без знака препинания
  в конце (однообразие с retail: `'Введите корректную сумму'`, не `'...инвестирования.'`).
- ⚠ При успехе `messageEl` уже перезаписывается числом (`script.js:226` `getElementById('profit')...`),
  поэтому «висячая» ошибка автоматически затирается. **Отдельной очистки не нужно.**

**`calculateCurrency` (script.js:390,396,402):**
- `const messageEl = document.getElementById('currency-result');` (`<span>` — `index.html:176`).
- 3 alert → `messageEl.textContent = '...'`.
- ⚠ Здесь `currency-result` имеет **класс** `profit-positive`/`profit-negative`, который JS ставит
  при успехе. При ошибке класс остаётся прежним — допустимо (текст ошибки важнее цвета). Если кодер
  хочет подчеркнуть — может `messageEl.className = 'error-message'`, но тогда при успехе класс
  вернётся (он переустанавливается в `script.js:418`). Не усложнять без нужды.

### Паттерн B — fetch-ошибка (2 alert: `fetchCbrRates` 368, и `fetchCbrRate` 22)

Fetch-ошибка отличается: нет «своего» поля-результата, пользователь нажал кнопку ↻.

**`fetchCbrRates` (script.js:368) — валюта:**
- Заменить `alert(...)` на запись в уже существующий `currency-cbr-exchange-rate`
  (`<span>` — `index.html:143`, подпись «Курс ЦБ: ... ₽»):
  ```js
  document.getElementById('currency-cbr-exchange-rate').textContent = 'нет данных';
  ```
- **Образец уже есть**: `fetchCbrMetals` делает ровно это (`metal-cbr-price` ← `'нет данных'`,
  см. `script.js:~497`). Копировать механику 1-в-1.
- При успехе `fetchCbrRates` уже перезаписывает этот span числом (`script.js:~362`), висячая
  ошибка затирается автоматически.

**`fetchCbrRate` (script.js:22) — ставка ЦБ, общая для 4 калькуляторов:**
- ⚠ Это единственный нетривиальный случай. Кнопок ↻ четыре (`.btn-fetch-cbr`), span'ов рядом с
  ними — несколько. Варианты (кодер выбирает простейший, обосновывает):
  1. **(рекомендация)** Не писать никуда конкретно — при ошибке ставка просто не обновится
     (останется прежняя в 4 полях). `alert` заменить на `console.error` (уже есть, `script.js:21`)
     + тихий пропуск. Пользователь поймёт по отсутствию изменения. Минимум surface, ноль новых DOM.
  2. Создать единый `<span id="rate-fetch-status">` в шапке/общем месте и писать туда — но это
     требует HTML-правки и дизайна «общего статусного места». **Отдельная задача** (пересекается с
     дизайн-редизайном `plan-design-saas.md`).
- **Решение архитектора: вариант 1.** Убрать `alert`, оставить `console.error`. Обоснование:
  ставка ЦБ — фоновая подгрузка, дефолт 21 уже стоит, при ошибке ничего не ломается; добавлять
  UI-якорь ради одного случая = раздувать контракт. Дизайн-задача позже даст единый toast.

### Что НЕ менять (anti-scope)
- **Не трогать** `calculateRetail` / `calculateMetal` / `calculateBankProfit`-расчёт / `calculateCurrency`-расчёт.
- **Не менять** тексты сообщений по сути (только пунктуацию для единообразия).
- **Не вводить** новый UI-элемент под fetch-статус (это в `plan-design-saas.md`).
- **Не трогать** `server.js`, эндпоинты, бизнес-логику.
- **Не добавлять** классы/стили без нужды; если везде единообразно — CSS не трогать.

## 🛡 Граничные случаи & Защита архитектуры

- **Висячая ошибка**: после показа inline-сообщения пользователь исправляет поле и жмёт
  «Рассчитать» → успех → span перезаписывается числом. Проверить, что это так во всех 4 функциях
  (в `calculateBankProfit`/`calculateCurrency` это уже работает — число пишется в тот же span).
- **`focus()` на виновное поле** — обязательно сохранять (UX: пользователь видит, где ошибка).
- **fetch-ошибка до первого успеха** (кеш пуст, ЦБ недоступен): `currency-cbr-exchange-rate`
  получает `'нет данных'`; при следующем успехе — число. Не оставлять висячий `'нет данных'`
  после успеха.
- **`fetchCbrRate` вызывается на `DOMContentLoaded`** (`script.js:~590`) — при ошибке на старте
  страницы alert бы выскочил сразу при загрузке (плохой UX). Убираем → тихая загрузка, ставка
  остаётся дефолтной 21. Это **улучшение**.
- **Никакого `innerHTML`** (§7) — только `textContent`. Сообщения статичны, экранирование не нужно.
- **PII в логах**: `console.error` пишет объект ошибки, не пользовательские данные (ставки/курсы —
  публичные). Не нарушает §7.

  отдельная задача; здесь только точечная замена alert → textContent.
